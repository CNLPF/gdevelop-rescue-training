# 机甲伙伴：救援基地 V0.3

面向 10—12 岁儿童的离线横版动作关卡。V0.3 在原有平台跳跃、换枪与商店系统上增加了天空救援线、两类飞行敌人和需要购买的制导导弹。项目使用 GDevelop 和本地 SVG／PNG 资源；核心玩法不依赖账号、在线素材、实时 AI 或网络服务。

项目当前包含两个场景：

- `RescueBase`：V0.3 完整关卡，默认场景。
- `TrainingRoom`：保留的基础跳跃、射击、商店与重试训练房，并叠加 V0.3
  的两类飞行敌人、制导导弹箱和三个补给试炼浮标。

## 打开与运行

本项目由 GDevelop 直接运行，不需要 `npm install`，也不需要 `npm run dev`。

1. 安装并打开 GDevelop **5.6.286**。
2. 选择“打开本地项目”，打开本目录的 `game.json`。
3. 等待场景加载后点击“预览”，再点击预览画面取得键盘焦点。

也可从工作区根目录双击或运行：

```powershell
.\launch-rescue-training.cmd
```

如果 Windows 找不到 GDevelop，请在启动脚本中确认 5.6.286 的可执行文件路径，或直接用该版本编辑器打开 `game.json`。打开项目与运行离线游戏不需要登录。

## 版本管理

本项目使用 Git 保存可回滚历史。正式 `game.json`、源码、测试、构建脚本和美术源文件进入提交；自动保存、预览项目、测试证据和临时候选文件不进入提交。变更与回滚流程见 [`docs/VERSION_CONTROL.md`](docs/VERSION_CONTROL.md)。

## 手工地图与源码边界

用户开始在 GDevelop 中直接维护地图后，保存后的 `game.json` 是场景实例和运行时事件的权威。`src/` 是可读源码与测试入口，修改它不会自动更新现有预览。

只读检查保存后的地图与稳定 Id：

```powershell
node .\scripts\inspect-game-json.cjs --scene=RescueBase --ids
node .\scripts\inspect-game-json.cjs --scene=RescueBase --details
```

检查器不会写入 `game.json`。完整的数据权威关系、事件流程、变量字典和地图耦合风险见 [`docs/GAME_ARCHITECTURE.md`](docs/GAME_ARCHITECTURE.md)。

**不要在手工编辑地图后直接运行旧的地图生成流程。** `build-base.cjs` 会按 `src/base/config.js` 中的历史坐标清空并重建场景实例；`--check` 和 `--output` 虽不覆盖正式文件，也会在内存中重建旧地图，因此不能作为新版编辑器地图的安全校验。

## 操作

| 按键 | 功能 |
|---|---|
| ← / → | 移动与转身 |
| 空格 | 跳跃；松开后再次按下可二段跳 |
| W | 能量枪连射；穿盾炮蓄力后松开发射；导弹锁定后松开发射 |
| Q | 在已拥有的能量枪、穿盾炮、制导导弹之间循环 |
| E | 领取武器、进入商店、使用训练靶或返回传送门 |
| 方向键 / Enter / Esc | 商店与传送门选择、确认、关闭 |
| R / Enter / Esc | 打开重开确认、确认新局、取消 |

自动瞄准只考虑生命仍大于 0、位于角色面向一侧、处于当前武器射程内且没有墙体遮挡的目标。候选评分使用“距离＋0.75 × 纵向距离”，因此横向目标略微优先，但明显更容易命中的高空目标仍会被选中。当前目标会保持到另一个目标至少好 20% 才切换，减少飞敌浮动造成的准星跳动；能量枪、穿盾炮和制导导弹共用这个目标与屏幕准星。

## 跨场景复用边界

`TrainingRoom` 与 `RescueBase` 共用同一套规则，而不是在两个场景里分别维护近似逻辑。新增系统应先判断它属于共享层还是场景层：

| 层 | 复用内容 |
|---|---|
| 共享规则 | 武器参数、目标筛选与评分、20% 粘性切换、锁定和蓄力状态、统一伤害、奖励防重、金币交接及购买校验 |
| 共享输入 | ←／→、空格、W、Q、E 与菜单按键状态；切枪、商店、掉坑和死亡时统一取消蓄力／锁定 |
| 共享表现 | HUD 布局、武器图标、准星、充能条、资源映射和完成记录字段 |
| 共享构建与测试 | `src/base/` 下的配置与规则、`src/art-v2.js`、`src/hud.js`、构建脚本、纯规则测试和 GDevelop 玩法测试入口 |
| 场景专属 | 地图和平台碰撞、敌人实例与数量、门和商店位置、教学阶段、完成条件、完成卡文案、镜头边界和背景 |

任何跨场景对象都使用稳定字符串 `Id` 作为逻辑标识，不使用 GDevelop 运行时数字对象 ID。统一弹丸数据契约为：

- `Bullet.TargetId`：string；空字符串表示无锁定目标。
- `Bullet.Locked`：boolean；表示发射瞬间是否取得锁定。
- `Bullet.Weapon`：string；取值为已配置武器标识。
- `Bullet.PierceShield`：boolean；只负责本次命中的护盾规则。

新增敌人、武器、特殊地形或新场景前，需要先确认以下契约，再写事件和素材：

1. 稳定 ID、分类统计字段和奖励是否只结算一次。
2. 自动瞄准资格、射程、遮挡、目标死亡和粘性切换规则。
3. 暂停、切枪、掉坑、死亡和返回检查点时，蓄力、锁定、弹丸与预警如何清理。
4. 掉坑保留哪些状态，生命耗尽的新局重置哪些状态，未消费金币如何交接。
5. GDevelop 变量的类型与初值是否一致，尤其是布尔值和字符串 ID。
6. 所需资源是正式原稿还是明确标记的本地占位，是否仍在同一画风与轮廓系统内。
7. 玩法测试是否能在不登录、不联网、不依赖 MCP 的情况下完成。

这套分层让关卡内容可以独立增加，同时把最容易产生回归的输入、瞄准、伤害、经济与 HUD 保持为单点实现。新场景只需提供场景数据和进度规则，不应复制一份 `combat.js` 后再单独修 bug。

## 关卡内容

`RescueBase` 宽 8400 像素，划分为 7 个连续区域：

1. 基地入口：安全跳跃与二段跳教学。
2. 巡逻走廊：巡逻机器人、移动炮台与动态增援。
3. 补给站：免费领取穿盾炮、练习靶和商店。
4. 护盾通道：正面盾牌、绕后攻击与蓄力穿盾。
5. 能源平台：地面和高低平台混合战斗。
6. 天空救援线：空港补给试炼、侦察无人机、装甲无人机、导弹和中继核心。
7. 救援出口：低风险收尾、最后商店、伙伴和完成卡。

全关有 22 名固定敌人：

| 敌人 | 数量 | 生命 | 主要机制 |
|---|---:|---:|---|
| 巡逻机器人 | 6 | 2 | 在区域边界内追击并发射非追踪弹 |
| 移动炮台 | 5 | 4 | 缓慢靠近并维持射击距离，发射非追踪弹 |
| 护盾守卫 | 4 | 8 | 追击、转向并射击；正面格挡普通弹，可绕后或穿盾 |
| 侦察无人机 | 4 | 3 | 水平和垂直靠近，在画面内发射非追踪弹 |
| 装甲无人机 | 3 | 10 | 靠近玩家并投下带落点预警的垂直炸弹 |

五种敌人共用一套“评估目标、靠近、保持距离、攻击”的逻辑，并保留各自的区域边界。巡逻机器人、移动炮台和护盾守卫会主动接近玩家；两类无人机会同时调整水平与垂直距离。所有远程攻击均不绘制瞄准引导线，弹丸不会自动追踪玩家。

巡逻走廊加入高低掩体和上层射击位，能源平台提供上下两条可切换路线，各区域使用配置中的 `Tempo` 调整攻击压力。敌人内部仍保留短暂蓄势时间，用于避免同一帧集中开火，但玩家界面不再显示炮台、无人机或炸弹的引导线／落点标记。

战斗区域还会按 `5—7` 秒的间隔生成随机增援，最多同时存在 3 名，类型覆盖巡逻机器人、移动炮台、护盾守卫、侦察无人机和装甲无人机五类。生成点均来自手工配置的安全站点，只会出现在当前战斗区、与玩家至少保持 220 像素距离，并避开补给站和跳跃教学区。随机增援拥有正常生命和攻击行为，但不掉落金币，避免反复刷取。商店等暂停状态会冻结生成和攻击计时。

敌人在真正生成弹丸前会再次检查当前画面、距离、垂直范围、墙体遮挡和暂停状态。飞机已经飞出画面或攻击条件失效时，本次攻击直接取消，不会补发一颗延迟弹。新生成的增援会同时获得生命标签，但不会创建瞄准引导线或炸弹落点标记。

地图固定放置 32 枚金币，22 名敌人每人奖励 3 枚，因此单局基础可获得收入为 98 枚。导弹补给试炼的收益另行记录且可重复获取，不混入地图探索收入。地图金币、敌人奖励、试炼收益和消费分别记录。

中继核心不会在进入天空救援线时立即激活；只有本区飞行敌人清空后，它才可被瞄准和命中。普通武器会被中继核心拒绝，制导导弹是摧毁核心、开启最终闸门所需的武器。

## 武器与经济

| 武器 | 获取方式 | 基础／升级伤害 | 说明 |
|---|---|---:|---|
| 能量枪 | 开局持有 | 1／2 | 0.30 秒连射，射程 600 |
| 穿盾炮 | 补给站免费领取 | 未蓄力 1／2；满蓄力 4／8 | 0.80 秒蓄力，满蓄力可穿盾 |
| 制导导弹 | 天空武器店购买，20 金币 | 无锁定 1／2；锁定 3／5 | 0.55 秒锁定，松开发射，升级 18 金币 |

导弹是中继核心和最终救援门的必需武器。空港商店提供不带时间压力的三目标补给试炼；每击破一个浮标奖励 4 金币，每轮最多 12 枚，可重复重置。即使进入空港时余额为零，也能通过两轮试炼凑够导弹价格。

两种旧武器可分别升级为 12 和 16 金币；三把武器可分别升级 18 金币；每处商店提供一次 5 金币的完整补血。升级不是通关必需。

## 失败与状态

- 掉坑：回到最初出生点，不扣生命、不刷新敌人、不重置金币和关卡进度；清除飞行中的弹丸并给敌人 0.8 秒攻击恢复时间。
- 生命耗尽或按 R 确认：开启新局，恢复敌人、地图金币、武器、升级、门和捷径；只保留尚未消费的金币余额。
- 已消费金币不会因新局退回。余额只在本次游戏预览内跨局保留，不跨关闭游戏存档。

## 教师演示流程

1. 从入口完成低台和二段跳，观察信标开门。
2. 用 W 击败走廊敌人，观察炮台和巡逻机器人靠近、转向并射击。
3. 在补给站按 E 免费领取穿盾炮，比较普通弹被盾牌挡住和满蓄力穿盾。
4. 进入天空救援线，在空港按 E 打开导弹商店；余额不足时选择“补给试炼”，击破三个浮标后返回商店。
5. 以 20 金币购买导弹，按住 W 观察锁定准星，松开后发射。
6. 击败两类无人机，用四发基础伤害导弹击破 12 点生命的中继核心。
7. 穿过开启的最终闸门到达救援出口，检查完成卡中的金币收支、敌人分类、武器发射／命中、导弹购买、掉坑次数和行动时间。

商店打开时世界暂停；鼠标点击按钮不是玩法依赖，完整路线可用键盘完成。

## 项目结构

- `game.json`：GDevelop 项目、场景、对象实例、事件和玩法测试。
- `docs/GAME_ARCHITECTURE.md`：数据权威、每帧事件流程、场景与实例变量字典、地图耦合和扩展契约。
- `src/base/config.js`：地图、区域、敌人、金币、商店、武器参数和纯规则。
- `src/base/input.js`：输入、换枪、蓄力／锁定、商店购买和试炼重置。
- `src/base/combat.js`：目标选择、统一伤害、奖励、飞行敌人状态机和弹丸追踪。
- `src/base/world.js`：金币、掉坑、传送门、分区推进和出口。
- `src/base/presentation.js`：HUD、预警、完成卡和真实交互记录。
- `src/base/runtime.js`：场景初始化、重试交接与模块组装。
- `src/training-aerial.js`：在五阶段训练房中接入 V0.3 飞行敌人、导弹和试炼，
  不改变原有教学推进。
- `src/shared/aiming.js`：两个场景共用的目标筛选、加权评分、粘性切换和射击方向解析。
- `src/art-v2.js`、`src/hud.js`：角色视觉代理与两场景共享 HUD；HUD 图标和
  文本使用同一组显式布局常量，避免实例缩放造成重叠。
- `assets/`：本地 SVG／PNG、资源清单和高清角色资源。
- `art-source/`：用户提供的美术包、说明和提取来源记录。
- `tests/*.test.js`：可由 Node 直接执行的纯规则测试。
- `tests/*.gameplay.js`：需要在 GDevelop 游戏测试环境运行的真实玩法脚本。
- `scripts/inspect-game-json.cjs`：只读检查布局、实例、稳定 Id 和关键变量的工具。
- `scripts/build-base.cjs`：历史配置驱动的项目重建工具；手工地图阶段不得直接用于覆盖当前场景实例。
